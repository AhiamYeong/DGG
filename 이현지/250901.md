## 하둡, 맵리듀스, 스파크 정리
## 1. 하둡 (Hadoop)

**하둡**은 대용량 데이터의 분산 저장 및 처리를 위한 오픈 소스 프레임워크. 핵심 목표는 **저렴한 하드웨어(commodity hardware)** 를 사용하여 대규모 클러스터를 구축하고, 데이터와 연산 작업을 분산 처리하여 비용 효율성을 높이는 것.

### 아키텍처

* **HDFS (Hadoop Distributed File System)** — 데이터를 블록 단위로 쪼개어 여러 노드에 저장하는 분산 파일 시스템. 각 블록은 기본적으로 복제본을 만들어 노드 실패에 대비.
* **YARN (Yet Another Resource Negotiator)** — 하둡 2.0부터 도입된 자원 관리 및 작업 스케줄링 시스템

### 주요 사용 사례

* 대규모 로그 데이터 분석
* 데이터 웨어하우스 구축
* 웹 크롤링 및 인덱싱

## 2. 맵리듀스 (MapReduce)

**맵리듀스**는 대규모 데이터 세트를 처리하기 위한 프로그래밍 모델이자 처리 엔진. 하둡 초기 버전의 핵심 처리 방식이었지만, 성능 한계로 인해 현재는 **스파크** 등으로 대체되는 추세.

### 동작 과정

1. **Input (입력)**: HDFS에 저장된 입력 데이터 파일을 읽음.
2. **Splitting (분할)**: 입력 데이터를 여러 개의 작은 입력 스플릿 으로 나눔.
3. **Mapping (맵)**: 각 입력 스플릿을 처리하는 Mapper 태스크가 생성. Mapper는 데이터를 `(key, value)` 쌍으로 변환하여 중간 결과를 생성함.
4. **Shuffling & Sorting (셔플링 & 정렬)**: Mapper가 생성한 중간 결과를 **동일한 키**를 가진 데이터끼리 모아 Reducer로 전달함. 이 과정에서 데이터가 네트워크를 통해 이동하고 정렬되며, 많은 디스크 I/O가 발생함.
5. **Reducing (리듀스)**: Reducer 태스크가 동일한 키를 가진 데이터를 그룹별로 받아 최종 결과를 생성함.
6. **Output (출력)**: 최종 결과가 HDFS에 저장됨.

### 단점

* 모든 **중간 결과가 디스크에 기록**되어 읽고 쓰는 과정이 반복되므로, **여러 단계를 거치는 복잡한 작업에서 속도가 매우 느림**.


## 3. 스파크 (Spark)

**스파크**는 맵리듀스의 단점을 극복하고 훨씬 빠르고 다양한 기능을 제공하는 **통합 분석 엔진**. 하둡 **HDFS 위에서 동작**하며, 데이터 처리의 사실상 표준으로 자리 잡음.

### 특징 및 기술

* **RDD (Resilient Distributed Dataset)** — 스파크의 핵심 데이터 구조. 여러 노드에 분산된 **읽기 전용** 데이터 컬렉션이며, 오류가 발생하면 원본 데이터를 재구성할 수 있는 **내결함성**을 가짐.
* **DAG (Directed Acyclic Graph) Scheduler** — 작업의 논리적 흐름을 DAG로 표현하고 이를 **최적화하여 실행**. 맵리듀스처럼 매번 디스크에 저장하지 않고, 필요한 연산만 **메모리 상에서 파이프라인**으로 연결해 처리 효율을 극대화 함.
* **인메모리(In-Memory) 연산**
  대부분의 중간 데이터를 **메모리**에 보관하여 디스크 I/O를 최소화함으로써 맵리듀스보다 **압도적으로 빠른 성능**을 제공함.
* **통합 라이브러리**

  * **Spark SQL**: SQL 쿼리로 구조화 데이터 처리
  * **Spark Streaming**: 실시간 데이터를 **마이크로 배치(micro-batch)** 로 처리
  * **MLlib**: 대규모 데이터용 머신러닝 알고리즘 라이브러리
  * **GraphX**: 그래프 및 그래프 병렬 연산 지원

### 주요 사용 사례

* 실시간 데이터 분석 및 스트리밍 처리
* 반복 연산이 많은 머신러닝 학습
* 대화형(Interactive) 데이터 탐색 및 분석
* 복잡한 다단계 **ETL(Extract, Transform, Load)** 작업
