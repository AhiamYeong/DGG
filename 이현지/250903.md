## 데이터베이스 설계 및 빅데이터 활용
### 1. 인덱스의 원리 및 빅데이터 적용
인덱스는 본문에서 중요한 항목을 찾아 위치를 기록해 둔 색인과 같은 역할을 함.

**1.1. 인덱스 종류**

- **클러스터형 인덱스**: 테이블당 1개만 생성할 수 있으며, 기본 키(PK) 생성 시 자동으로 만들어짐. 행 데이터를 인덱스 열에 맞춰 정렬하기 때문에 데이터 자체가 정렬됨. 논클러스터형 인덱스보다 검색 속도가 더 빠름.
- **논클러스터형 인덱스**: 테이블당 여러 개를 생성할 수 있고, 필요에 따라 추가할 수 있음. 데이터 페이지와 별도로 인덱스 페이지를 생성하며, 정렬된 열과 데이터 위치 포인터를 저장함.

**1.2. 인덱스의 장단점**
- 장점: 검색 속도를 향상시키고 시스템 부하를 줄여줌.
- 단점: 관리를 위해 추가 공간이 필요하고, UPDATE나 DELETE 같은 DML 작업에 시간이 더 소요됨. 잘못 사용하면 성능에 악영향을 미칠 수 있음.

**1.3. 힌트(Hint)** : 
쿼리 최적화 도구가 원하는 인덱스를 사용하지 않을 때, 개발자가 직접 인덱스 사용을 지정하는 기능. USE INDEX, FORCE INDEX, IGNORE INDEX 등이 있음.

### 2. DB 정규화와 반정규화
**2.1. 데이터 타입 선택**: 저장 용량을 고려해 데이터 타입은 저장 데이터에 비해 과하지 않게, 가장 작은 것을 선택해야 용량 낭비를 줄이고 속도를 높일 수 있음.

**2.2. DB 정규화** : 테이블 간 중복 데이터를 최소화하고 데이터의 무결성을 유지하는 과정. 하지만 JOIN을 많이 사용하게 되어 응답 시간 저하를 초래할 수 있음.

**2.3. DB 반정규화** : 시스템 성능 향상이나 개발 편의성을 위해 정규화 원칙을 의도적으로 위배하는 과정. 정규화를 먼저 수행한 후에 진행해야 함.

- **고려 대상**: 대량의 또는 특정 범위의 데이터를 자주 처리하거나, 요약/집계 정보가 자주 필요하거나, JOIN으로 인한 성능 저하가 예상될 때.
- **반정규화 방법**: 1:1 또는 1:N 관계의 테이블 병합, 수직/수평 분할, 통계 테이블과 같은 중복 테이블 추가 등이 있음.

### 3. 하둡, 스파크 환경에의 적용
전통적인 RDBMS의 개념을 빅데이터 환경에 맞게 재해석하여 적용할 수 있음.

**3.1. 인덱스의 원리 활용: 데이터 파티셔닝**

하둡의 HDFS는 파일 시스템이므로 직접적인 인덱스 구조를 가질 수 없음. 대신, 데이터 파티셔닝을 통해 인덱스의 원리인 검색 속도 향상을 구현할 수 있음.
- 적용: 승하차 데이터를 날짜나 노선별로 HDFS의 별도 폴더에 저장. 스파크는 특정 폴더만 읽어오도록 지정하여 전체 데이터를 읽는 것보다 훨씬 빠른 성능을 낼 수 있음.

**3.2. 반정규화의 원리 활용: 분석 목적에 맞는 통합 데이터 생성**

분산 시스템인 하둡과 스파크에서는 JOIN 연산이 비효율적이므로, 반정규화 선택하여 성능 높임.

- 적용: 승하차 데이터와 같은 여러 소스의 데이터를 분석 전에 미리 JOIN하여 하나의 넓은 데이터 파일로 만들어 저장함. 이렇게 통합된 데이터 파일을 스파크가 읽으면 JOIN 없이 바로 분석을 시작할 수 있어 작업 속도를 비약적으로 향상시킬 수 있음.
