## 업무 흐름  
1. 데이터 저장: 기존 1년치 승하차 데이터를 하둡에 저장.
2. 데이터 분석: 스파크를 이용해 하둡의 데이터를 분석하고 예측 모델 생성.
3. 결과 제공: 분석 결과를 애플리케이션 서버에서 사용할 수 있는 데이터베이스에 저장.

## 요약
- 하둡: 1년치 데이터를 저장하는 역할.
- 스파크: 하둡의 데이터를 읽어와 복잡한 통계 분석과 예측 모델 학습을 수행하는 역할.
- 서버: 스파크가 만들어낸 결과를 조회하여 사용자에게 제공하는 역할.

## 정리
### 1. 하둡 (Hadoop) - 유일한 데이터 저장소
프로젝트에서 사용하는 모든 과거 데이터를 저장하는 중앙 데이터 웨어하우스. 1년간의 방대한 승하차 데이터를 안정적으로 보관하는 역할.
### 적용
- 1년간의 승하차 데이터를 수집하여 하둡 HDFS에 일괄적으로 업로드.
- 스파크가 이 데이터를 읽어서 분석하는 유일한 소스가 됨.

### 2. 스파크 (Spark) - 데이터 분석 및 예측 엔진
하둡에 저장된 모든 데이터를 분석하여 혼잡도 패턴을 발견하고, 이를 기반으로 예측 결과를 생성하는 핵심 엔진.

### 적용:
- 배치 작업: 스파크는 HDFS에 있는 1년치 데이터를 한 번에 읽어와 다음의 복잡한 연산을 수행.
- 혼잡도 패턴 분석: 노선과 정류장별로 평균 승하차 인원을 계산하고, 혼잡도가 낮은 시간대와 경로를 식별.
- 예측 모델 학습: 분석된 패턴을 기반으로, 내일 이 시간대의 혼잡도를 예측하는 머신러닝 모델을 학습.
- 결과 생성: "덜 붐비는 경로"에 대한 최종 추천 경로 목록과, 각 기능에 필요한 예측 값을 계산하여 저장.

### 3. 서버 - 최종 결과 제공
스파크가 분석한 결과 데이터를 받아서 사용자에게 서비스 함.

### 적용:
- 스파크 배치 작업이 완료되면, 그 결과를 서비스 서버가 빠르게 조회할 수 있는 데이터베이스에 저장.
- 애플리케이션 서버는 사용자의 요청을 받으면 이 데이터베이스를 쿼리하여 미리 계산된 최적의 경로를 즉시 반환.
