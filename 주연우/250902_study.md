# Spark
## 1. Spark란?
Apache Spark는 대규모 데이터 처리 및 분석을 위한 **오픈소스 분산 처리 프레임워크**이다. 

**Hadoop의 단점을 보완하며 등장.**
- 하둡의 MapReduce는 디스크 기반 연산으로 인해 속도가 느리고, 배치 처리(batch processing)만 가능하다는 한계가 존재.
- 반면 Spark는 메모리 기반(In-Memory) 연산을 통해 성능을 크게 개선했으며, 배치 처리뿐만 아니라 실시간 스트리밍 처리, SQL 질의, 머신러닝, 그래프 분석까지 지원하는 범용 빅데이터 분석 플랫폼으로 발전.

### Hadoop vs. Spark
| 구분           | Hadoop (MapReduce)       | Apache Spark                      |
| ------------ | ------------------------ | --------------------------------- |
| **처리 방식**    | 디스크 기반 (중간 결과를 HDFS에 저장) | 메모리 기반 (In-Memory)                |
| **속도**       | 상대적으로 느림 (반복 작업 비효율)     | 최대 100배 빠름                        |
| **프로그래밍 모델** | Java 기반, 복잡              | Scala, Python, Java, R API 제공, 간결 |
| **지원 기능**    | 배치 처리 중심                 | 배치, 스트리밍, SQL, ML, 그래프            |
| **데이터 구조**   | Key-Value 중심             | RDD, DataFrame, Dataset           |
| **확장성**      | 우수 (수천 노드)               | 동일하게 수천 노드 확장 가능                  |
| **활용 사례**    | 로그 분석, 단순 집계             | 실시간 분석, 추천 시스템, IoT, AI/ML        |

## 2. Spark의 특징
### RDD (Resilient Distributed Dataset)
RDD는 스파크의 모든 연산이 이루어지는 기본 데이터 구조.
**RDD(회복 가능한 분산 데이터셋)**는 클러스터의 여러 노드에 분산되어 병렬로 처리될 수 있는, **변경 불가능한(immutable)** 데이터 요소들의 집합입니다.

### 인메모리 컴퓨팅과 지연 연산
1) **인메모리 컴퓨팅**
스파크가 맵리듀스보다 최대 100배 빠를 수 있는 가장 큰 이유는 중간 데이터를 디스크가 아닌 **메모리에 캐시(Cache)**을 사용하기 때문.

2) **지연연산과 DAG**
두 가지 스파크 연산
- **변환 (Transformation)**: 기존 RDD로부터 새로운 RDD를 생성하는 연산. (예: map(), filter(), join()) 변환 연산은 '게으르게(Lazy)' 동작하여, 호출되는 즉시 실행되지 않고 어떤 연산을 수행해야 하는지에 대한 '실행 계획'만 정의
- **액션 (Action)**: 실제 연산을 촉발하고, 최종 결과를 드라이버 프로그램으로 반환하거나 외부 저장소에 저장하는 연산. (예: count(), collect(), saveAsTextFile())

## 3. 우리 프로젝트에 Spark 적용 플로우
### 문제 정의
- 목표: 피로도가 최소화된 교통 경로 추천
- 데이터
    - 승하차 데이터
    - 혼잡도 데이터
    - 환승 데이터

### 처리 단계
1️⃣ **데이터 수집**
spark.read 명령어로 HDFS에 저장된 과거 운행 기록, 노선 정보 파일을 DataFrame으로 읽어온다.

2️⃣ **데이터 처리리**
- Spark SQL과 MLlib을 사용해 HDFS에 저장된 과거 데이터를 분석
- '시간/요일/날씨별 평균 피로도' 같은 통계 데이터를 미리 계산
- 이 결과들은 **데이터베이스(RDBMS)**에 저장

3️⃣ **경로 추천 시 데이터 활용**
- 사용자가 경로를 요청하면, 추천 엔진이 Spark가 만들어 둔 데이터를 조회
- 1) Elasticsearch에서 **가중치**를 가져옵니다.
- 2) 데이터베이스에서 **피로도**를 가져옵니다.

두 데이터를 조합하고 환승 저항 등을 추가로 계산해 **'최종 피로도 점수'**가 가장 낮은 경로를 사용자에게 추천합니다.
