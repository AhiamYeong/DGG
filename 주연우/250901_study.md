# 빅데이터의 처리: Hadoop
## 1. 하둡이란?
기존의 단일 서버에 설치된 관계형 데이터베이스(RDBMS) 시스템으로 빅데이터 처리가 불가함에 따라, 수평적으로 확장하여 즉, **컴퓨터 여러 대를 묶어 하나의 시스템처럼** 사용하는 분산 컴퓨팅이 주목받게 되었다. **하둡은 분산 컴퓨팅 환경에서 빅데이터를 효율적으로 다루기 위한** 오픈소스 프레임워크이다.

**하둡의 두가지 핵심 기능**
1. 대용량 파일의 분산 저장: HDFS (Hadoop Distributed File System)
2. 분산 저장된 데이터의 병렬 처리: MapReduce (맵리듀스)

### 우리 프로젝트에서의 하둡
- 다양한 빅데이터(승하차 데이터, 혼잡도, 환승데이터) 분산 저장
- 데이터의 병렬 처리

## 2. HDFS: 분산저장 시스템
- **대용량 파일 저장**: 수백 MB, GB, TB 단위의 매우 큰 파일을 저장하는 데 최적화  
- **하드웨어 장애 감지 및 복구**: 저렴한 범용 하드웨어를 사용하므로 하드웨어 장애는 일상적인 것으로 간주하며, 이에 자동으로 대처  
- **스트리밍 방식의 데이터 접근**: 한 번 저장된 데이터는 수정되기보다는 주로 읽기 작업에 사용되며, 전체 데이터를 처음부터 끝까지 순차적으로 읽는 작업에 높은 처리량을 제공  

### HDFS 아키텍쳐
HDFS는 하나의 마스터 서버와 여러 개의 슬레이브 서버로 구성되는 **마스터-슬레이브(Master-Slave) 아키텍처**를 따른다.

[HDFS 아키텍처 다이어그램: 중앙에 NameNode 1대, 주변에 여러 대의 DataNode가 연결된 형태]

- **네임노드 - 마스터**
    - 전체 파일 시스템의 메타데이터를 관리하는 컨트롤 타워.
    - 클라이언트가 파일에 접근하려면 반드시 네임노드를 통해야 함.

- **데이터노트 - 슬레이브**
    - 실제 데이터를 블록 단위로 저장하는 저장소.
    - 데이터 노드는 주기적으로 네임노드에 하트비트(Heartbeat)를 보내 자신의 상태를 알리고 자신이 보관 중인 블록 목록을 보고한다.

### HDFS 데이터 처리 흐름
**파일 쓰기 (Write)**
- 클라이언트는 네임노드에게 파일 쓰기를 요청.
- 네임노드는 파일 경로, 권한 등을 확인하고, 해당 파일의 블록들을 저장할 데이터노드 목록을 클라이언트에게 알린다.
- 클라이언트는 첫 번째 데이터노드에 데이터를 전송. 데이터를 받은 첫 번째 데이터노드는 그 데이터를 두 번째 데이터노드에, 두 번째는 세 번째 데이터노드에 파이프라인 형태로 전달하여 복제본을 생성.
- 모든 복제가 완료되면 클라이언트에게 쓰기 완료를 알린다.

**파일 읽기 (Read)**
- 클라이언트가 네임노트에 파일 읽기 요청
- 네임노드는 해당 파일의 블록들이 어느 데이터노드들에 저장되어 있는지 위치 정보를 클라이언트에 전달
- 클라이언트는 네임노드가 알려준 데이터노드 중 가장 가까운 노드에 직접 접속하여 데이터 블록을 순차적으로 읽어옴.

## 3. 분산 처리 엔진: MapReduce와 YARN
HDFS에 데이터를 쌓았다면, 데이터를 분석하고 처리할 엔진이 필요. 맵리듀스와 YARN이 하둡의 **분산 처리 엔진**이 된다.

### MapReduce
맵리듀스는 대용량 데이터를 병렬로 처리하기 위한 간단하면서도 강력한 프로그래밍 모델. 개발자가 Map 함수와 Reduce 함수를 정의하면 <데이터 분산, 병렬 처리, 장애 복구 등 복잡한 분산 시스템 로직을 알아서 처리해 준다.

- 작동원리
1. Map 단계
- 입력 데이터를 key-value 쌍으로 나눔
- 여러 노드에서 병렬적으로 데이터를 전처리 (필터링, 그룹화 준비)
2. Reduce 단계
- Map 단계에서 나온 Key를 기준으로 합침
- Key별로 Value를 집계/연산



### YARN
자원 관리 기능과 데이터 처리 기능을 분리한 것.  
맵리듀스가 하둡 클러스터의 자원을 공유하며 사용할 수 있도록 관리.  

- 구성요소
    - ResourceManager (RM)
    클러스터 전체 자원을 관리하는 관리자.
    어떤 노드에서 어떤 작업을 실행할지 스케줄링.
    - NodeManager (NM)
    각 워커 노드에서 실행되는 에이전트.
    해당 노드의 CPU, 메모리 같은 자원 사용을 모니터링하고 RM에 보고.
    - ApplicationMaster (AM)
    하나의 애플리케이션 실행을 담당하는 매니저.
    자원 요청, 작업(Task) 배치, 실패 시 재시도 등을 담당.
    - Container
    실제 작업이 실행되는 단위. (CPU + 메모리 자원 단위로 할당됨)

- 장점
    - 다양한 분산 처리 엔진이 같은 클러스터 자원을 공유 가능
    - 확장성이 향상됨

## 4. 우리 프로젝트의 하둡 기반 데이터 처리 흐름
### 1️⃣ 데이터 수집 & 저장 (HDFS)
- 데이터 종류
    - 승하차 데이터 (버스/지하철 탑승 기록)
    - 혼잡도 데이터 (지하철 혼잡도 데이터)
    - 환승 데이터 (노선 연결 관계, 이동 시간, 인원)
- 저장 방식
    - HDFS에 저장
    - 데이터를 여러 블록으로 나눠 클러스터에 분산 저장 → 장애 복구 & 확장성 확보

### 2️⃣ 데이터 처리 (MapReduce)
(1) Map 단계
- 데이터를 Key-Value 쌍으로 분할
- 피로도 가중치 부여 예시:
    - 환승 구간 → +10 (거리 가중치)
    - 혼잡도 높음 → *1.2
    - 심야 시간 → +5

(2) Shuffle & Sort 단계
- 같은 구간(출발-도착)별 데이터 그룹화 및 정렬

(3) Reduce 단계
- 구간별 피로도 합산/평균 계산
- 예시:
```강남역 → 삼성역 : (승하차 800, 혼잡도 높음, 환승 1회) → 총 피로도 = 12```

### 3️⃣ 데이터 처리 흐름도
```
[데이터 수집]
        ↓
      [HDFS]
        ↓
[YARN 위 MapReduce Job]
  - 승하차 집계
  - 혼잡도 분석
  - 환승 불이익 반영
        ↓
[경로별 피로도 점수 산출]
        ↓
 [HDFS/HBase 저장]
        ↓
[추천 API → 사용자 앱]
```
