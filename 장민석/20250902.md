## 0. 개요

* 목표: `s3://<raw-bucket>/bus_monthly/`의 CSV를 Glue Catalog로 테이블화하고, Athena CTAS로 **Parquet + 파티션(ym, hour)** 테이블을 만듭니다.
* 결과물:

  * Glue Database: `raw_transit`, `curated`
  * RAW 테이블(자동 또는 수동 등록)
  * Curated 테이블: `curated.bus_hourly` (Parquet, partition: `ym`, `hour`)
* 권장 리전: 예시로 `ap-southeast-2 (Sydney)` 사용. 본인 계정 리전에 맞춰 변경하세요.

## 2. 카탈로그 & 접근 (Glue Catalog + Lake Formation)

### 개념

* Glue Data Catalog: S3 파일을 **테이블(스키마)** 로 등록하는 메타스토어
* Lake Formation(LF): DB/테이블/S3 경로에 대한 **데이터 권한** 제어

### 목적

* RAW CSV가 있는 `s3://$RAW_BUCKET/bus_monthly/`를 `raw_transit` DB의 테이블로 등록
* **생성 주체(크롤러/ETL 역할)** 에 DB/테이블/데이터 위치 권한을 부여하여 실제 테이블 생성 및 조회 가능 상태 확보

### 방법

#### 콘솔

1. Glue → Data Catalog → Databases → Create database → `raw_transit`
2. Glue → Crawlers → Create

   * Data source: `s3://$RAW_BUCKET/bus_monthly/` (**끝에 `/` 필수**)
   * Custom CSV Classifier

     * 헤더가 정상(영문/ASCII): **Contains header = Present**
     * 헤더가 한글/숫자 시작: **Contains header = Absent** (이 경우 Athena에서 `col0..` 매핑)
   * Output: Database=`raw_transit`, Table prefix=`raw_`
   * Role: `ROLE_NAME` (예: `AWSGlueServiceRole-raw-crawler`)
3. Lake Formation → Permissions → Grant

   * Principal: `ROLE_NAME`
   * Database `raw_transit`: `CREATE_TABLE, ALTER, DESCRIBE`
   * Tables in `raw_transit` (All + future): `SELECT, DESCRIBE, ALTER, DROP`
   * Data locations: `s3://$RAW_BUCKET/` → `DATA_LOCATION_ACCESS`

#### CLI(선택)

```bash
# DB 만들기
aws glue create-database --region $REGION --database-input Name=raw_transit

# 역할 ARN 조립
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ROLE_ARN="arn:aws:iam::$ACCOUNT_ID:role/$ROLE_NAME"

# LF: 버킷 등록(이미 등록되어 있으면 무시)
aws lakeformation register-resource --region $REGION \
  --resource-arn arn:aws:s3:::$RAW_BUCKET --role-arn "$ROLE_ARN" || true

# LF: 권한 부여(역할 기준)
aws lakeformation grant-permissions --region $REGION \
  --principal DataLakePrincipalIdentifier="$ROLE_ARN" \
  --resource '{"Database":{"Name":"raw_transit"}}' \
  --permissions CREATE_TABLE ALTER DESCRIBE

aws lakeformation grant-permissions --region $REGION \
  --principal DataLakePrincipalIdentifier="$ROLE_ARN" \
  --resource '{"Table":{"DatabaseName":"raw_transit","TableWildcard":{}}}' \
  --permissions SELECT DESCRIBE ALTER DROP

aws lakeformation grant-permissions --region $REGION \
  --principal DataLakePrincipalIdentifier="$ROLE_ARN" \
  --resource "{\"DataLocation\":{\"ResourceArn\":\"arn:aws:s3:::$RAW_BUCKET\"}}" \
  --permissions DATA_LOCATION_ACCESS
```

### 주의점

* 관리자(사용자) 권한과 **역할 권한**은 별개입니다. 생성 주체(크롤러/ETL 역할)에 권한이 없으면 테이블이 **안 생기거나 안 보입니다**.
* Glue/Athena/LF/S3 **리전 통일** 필수.
* S3 경로 **대소문자/끝 슬래시** 확인.

### Q\&A

* Q. 크롤러가 성공인데 테이블이 안 보입니다.
  A. ① LF에서 **역할 권한 누락** ② 경로 오타 또는 빈 프리픽스 ③ 헤더 문제(숫자 시작/비ASCII) → Absent 분류기로 생성 후 Athena에서 `col0..` 매핑.

### 빠른 확인

* Athena 콘솔 → Query editor → Database=`raw_transit` → `SHOW TABLES IN raw_transit;`
* RAW 테이블이 보이면 `SELECT * FROM raw_transit.<테이블명> LIMIT 5;` 실행

## 3. CSV → Parquet/Partition 변환 (Athena CTAS)

### 개념

CSV는 비효율적입니다. **Parquet(열 지향) + 파티션(ym, hour)** 으로 바꾸면 스캔량이 줄어 **비용과 시간이 절감**됩니다.

### 목적

* Curated Database `curated` 생성
* `curated.bus_hourly` 테이블 생성 (Parquet, partition: `ym`, `hour`)

### 방법

#### 헤더가 정상(영문/ASCII)인 RAW 테이블을 사용하는 경우

```sql
CREATE DATABASE IF NOT EXISTS curated;

WITH src AS (
  SELECT
    regexp_replace(사용년월,'[^0-9]','') AS ym,
    노선ID AS line_id, 노선번호 AS line_no, 노선명 AS line_name,
    표준버스정류장ID AS station_id, 버스정류장ARS번호 AS ars_id, 역명 AS station_name,
    "00시승차총승객수" AS in00, "00시하차총승객수" AS out00,
    "1시승차총승객수"  AS in01, "1시하차총승객수"  AS out01,
    -- ... 2~23시 동일 패턴 ...
    "23시승차총승객수" AS in23, "23시하차총승객수" AS out23
  FROM raw_transit.<raw_table>
),
expanded AS (
  SELECT
    'bus' AS mode, ym, h AS hour,
    line_id, line_no, line_name, station_id, ars_id, station_name,
    GREATEST(0,i) AS in_cnt_m,
    GREATEST(0,o) AS out_cnt_m
  FROM src
  CROSS JOIN UNNEST(
    SEQUENCE(0,23),
    ARRAY[in00,in01,in02,in03,in04,in05,in06,in07,in08,in09,in10,in11,in12,in13,in14,in15,in16,in17,in18,in19,in20,in21,in22,in23],
    ARRAY[out00,out01,out02,out03,out04,out05,out06,out07,out08,out09,out10,out11,out12,out13,out14,out15,out16,out17,out18,out19,out20,out21,out22,out23]
  ) AS t(h,i,o)
)
CREATE TABLE curated.bus_hourly
WITH (
  external_location = 's3://<CURATED_BUCKET>/bus_hourly/',
  format = 'PARQUET',
  partitioned_by = ARRAY['ym','hour']
) AS
SELECT
  mode, ym, hour, line_id, line_no, line_name, station_id, ars_id, station_name,
  in_cnt_m, out_cnt_m, (in_cnt_m + out_cnt_m) AS total_flow_m
FROM expanded;
```

#### 헤더 문제가 있어 Absent 분류기로 RAW를 만든 경우(`col0..` 매핑)

```sql
CREATE DATABASE IF NOT EXISTS curated;

WITH src AS (
  SELECT
    regexp_replace(col0,'[^0-9]','') AS ym,         -- 사용년월
    col1 AS line_id, col2 AS line_no, col3 AS line_name,
    col4 AS station_id, col5 AS ars_id, col6 AS station_name,
    col7 AS in00,  col8 AS out00,
    col9 AS in01,  col10 AS out01,
    -- ... 순서대로 23시까지 매핑 ...
    col53 AS in23, col54 AS out23
  FROM raw_transit.<raw_table_noheader>
),
expanded AS (
  SELECT
    'bus' AS mode, ym, h AS hour,
    line_id, line_no, line_name, station_id, ars_id, station_name,
    GREATEST(0,i) AS in_cnt_m, GREATEST(0,o) AS out_cnt_m
  FROM src
  CROSS JOIN UNNEST(
    SEQUENCE(0,23),
    ARRAY[in00,in01,in02,in03,in04,in05,in06,in07,in08,in09,in10,in11,in12,in13,in14,in15,in16,in17,in18,in19,in20,in21,in22,in23],
    ARRAY[out00,out01,out02,out03,out04,out05,out06,out07,out08,out09,out10,out11,out12,out13,out14,out15,out16,out17,out18,out19,out20,out21,out22,out23]
  ) AS t(h,i,o)
)
CREATE TABLE curated.bus_hourly
WITH (
  external_location = 's3://<CURATED_BUCKET>/bus_hourly/',
  format = 'PARQUET',
  partitioned_by = ARRAY['ym','hour']
) AS
SELECT * FROM expanded;
```

### 주의점

* `external_location`을 반드시 명시합니다. 경로가 꼬이면 이후 관리가 어렵습니다.
* 파티션을 과도하게 세분화하면 소파일이 늘어 성능이 떨어집니다. `ym/hour`부터 시작하세요.

### Q\&A

* Q. CTAS를 다시 실행하면 어떻게 되나요?
  A. 보통 **새 테이블/새 경로**로 생성하는 것을 권장합니다. 증분 적재는 2일차에서 다룹니다.

### 빠른 확인

```sql
SELECT COUNT(*) FROM curated.bus_hourly;
SELECT ym, hour, COUNT(*) FROM curated.bus_hourly GROUP BY 1,2 ORDER BY 1,2;
```

## 4. 파티션 등록/투영(Partition Projection)

### 개념

Partition Projection을 설정하면 새로 추가된 `ym/hour` 파티션을 **REPAIR 없이 자동 인식**할 수 있습니다.

### 목적

증분 파일이 들어와도 별도의 메타 작업 없이 즉시 쿼리 가능하게 만들기

### 방법

```sql
ALTER TABLE curated.bus_hourly SET TBLPROPERTIES (
  'projection.enabled'='true',
  'projection.ym.type'='integer',
  'projection.ym.range'='202401,205012',
  'projection.hour.type'='integer',
  'projection.hour.range'='0,23',
  'storage.location.template'='s3://<CURATED_BUCKET>/bus_hourly/ym=${ym}/hour=${hour}/'
);
```

### 주의점

* `storage.location.template` 경로는 실제 S3 폴더 구조와 정확히 일치해야 합니다.
* Projection을 쓰지 않는다면 `MSCK REPAIR TABLE curated.bus_hourly;` 로 파티션을 등록해야 합니다.

### Q\&A

* Q. 특정 `ym`이 조회되지 않습니다.
  A. `range` 범위 밖이거나 템플릿 오탈자 가능성이 높습니다.

### 빠른 확인

```sql
SELECT COUNT(*) FROM curated.bus_hourly
WHERE ym=202505 AND hour BETWEEN 7 AND 9;
```

## 5. 데이터 품질 점검(기본 규칙 5개)

### 개념

이상치/누락을 조기에 탐지하기 위해 **쿼리로 규칙을 고정**해 둡니다.

### 목적

실수·오입력·인코딩 문제를 조기에 발견하고 추적 가능한 로그를 남깁니다.

### 방법

```sql
-- 1) 음수/NULL
SELECT * FROM curated.bus_hourly
WHERE in_cnt_m < 0 OR out_cnt_m < 0
   OR line_id IS NULL OR station_id IS NULL
LIMIT 100;

-- 2) 시간 범위
SELECT ym, MIN(hour) AS min_h, MAX(hour) AS max_h, COUNT(*) AS n
FROM curated.bus_hourly GROUP BY ym;

-- 3) 중복 키
SELECT ym, hour, line_id, station_id, COUNT(*) c
FROM curated.bus_hourly GROUP BY 1,2,3,4 HAVING c>1;

-- 4) 상위 0.1% 이상치
SELECT * FROM curated.bus_hourly
WHERE total_flow_m >
 (SELECT approx_percentile(total_flow_m, 0.999) FROM curated.bus_hourly)
LIMIT 100;

-- 5) 월합 검증
SELECT ym, SUM(total_flow_m) AS total
FROM curated.bus_hourly GROUP BY ym ORDER BY ym;
```

### 주의점

* Athena Workgroup의 **Query results location**을 고정해 결과를 보존하세요.
* 출퇴근 피크는 원래 값이 큽니다. 임계치를 적절히 조정하세요.

### Q\&A

* Q. 한글이 깨져 보입니다(CP949).
  A. Parquet 변환 후 소비하거나 원본을 UTF-8로 저장하면 완화됩니다.

### 빠른 확인

* 규칙 중 1\~2개를 실행하여 샘플 레코드를 확인합니다.

## 6. 비용·성능 튜닝(습관화)

### 개념

스캔량이 곧 비용과 성능입니다. **파티션 프루닝**과 **필요 컬럼만 SELECT** 하는 습관이 중요합니다.

### 목적

일상 쿼리에서 자동으로 비용과 시간 절감

### 방법

```sql
SELECT line_id, station_id, total_flow_m
FROM curated.bus_hourly
WHERE ym=202505 AND hour BETWEEN 7 AND 9;
```

* Athena Workgroup: **Enforce query limits**에서 **Bytes scanned limit** 설정
* 파일 크기: 128\~512MB로 적절히 묶이도록 CTAS를 설계

### 주의점

* `SELECT *` 사용을 지양하세요.
* 파티션 컬럼(ym, hour)을 반드시 WHERE 절에 포함하세요.

### Q\&A

* Q. 갑자기 느려지거나 비용이 급등했습니다.
  A. 최근 쿼리에서 **파티션 필터 누락** 또는 \*\*SELECT \*\*\* 사용 여부, 소파일 증가 여부를 확인하세요.

### 빠른 확인

* Athena 쿼리 상세에서 “Data scanned” 바이트를 수시로 확인하세요.
