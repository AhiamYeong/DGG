### Android 구조 설계: MVVM

- MVVM이라는 구조가 있다 (Model-View-ViewModel)
  - UI 개발을 위한 디자인 패턴 중 하나
  - UI와 비즈니스 로직을 분리해서 개발할 수 있으므로, 모바일 프레임워크 처음 접하는 사람들에게 추천한다고
  - 리액트와 매핑해보니 이해가 괜찮은 것 같아서 채택
- **Model**: ViewModel이 조작하는 핵심 데이터 & 비즈니스 로직.
  - React에서 const [user, setUser]의 'user'변수에 담기는 실제 사용자 정보.
  - API 호출을 통해 서버에서 받아오는 데이터, 로컬 스토리지 데이터, 전역 상태관리 데이터 등 ...
  - 비즈니스 로직: 사용자 인증, 상품 추가/삭제, 결제 처리, 데이터 유효성 검사 등.
- **View**: UI (XML, StoryBoard, Jetpack Compose 등). ViewModel의 데이터를 Observe해 화면을 업데이트. 입력 부분을 ViewModel에 전달.
  - React의 JSX 컴포넌트.
- **ViewModel**: View - Model 사이의 중개자. View의 데이터를 가공하고, Model의 데이터 가져와 View에 전달. (추상적이라 아직 이해가 안 된다)

  - React의 커스텀 훅.

- MVVM의 장점 (AI said)

  - 관심사의 분리: UI(View)와 비즈니스 로직(Model, ViewModel)이 명확하게 분리되어 있어, 각 부분을 독립적으로 개발하고 테스트하기 쉬워요. 예를 들어, 디자이너가 UI를 수정하는 동안 개발자는 백그라운드 로직을 계속 작업할 수 있습니다.

  - 테스트 용이성: ViewModel은 View와 분리되어 있기 때문에 UI 없이도 단위 테스트(Unit Test)를 할 수 있습니다. 이는 개발 속도와 코드의 안정성을 높이는 데 크게 기여합니다.

  - 재사용성: 동일한 ViewModel을 여러 개의 View에서 사용할 수 있어요. 예를 들어, 웹뷰와 네이티브 UI가 같은 데이터를 사용해야 할 때 하나의 ViewModel로 처리할 수 있습니다.

  - 유지보수 용이성: 코드의 구조가 명확하기 때문에 기능 추가나 버그 수정이 쉬워져요. 복잡한 앱일수록 이 장점이 더욱 두드러집니다.
